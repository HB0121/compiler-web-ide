# 智慧园区设备运维管理平台权限方案

## 一、设计说明

本方案只定义智慧园区设备运维管理平台的业务角色、页面访问权限和操作权限。权限数据表、菜单表、角色表、授权关系表由基础框架提供，本项目不单独设计权限相关数据库表。

权限控制建议采用“角色 + 菜单 + 按钮/操作标识”的方式实现：

1. 页面权限控制用户能否进入某个业务页面。
2. 操作权限控制用户能否执行新增、编辑、删除、分派、审核、出入库、发布等动作。
3. 数据权限可结合框架组织架构字段 `level_mark_id`、`level_mark_value` 控制可见范围。
4. 前端根据权限标识控制菜单、按钮、表格操作列和详情页动作。
5. 后端接口仍需做权限校验，前端隐藏按钮不能替代后端鉴权。

## 二、角色定义

| 角色编码 | 角色名称 | 角色定位 |
|---|---|---|
| `ops_admin` | 运维主管 | 负责全局运维管理、工单分派、审核、报表查看和基础业务数据维护 |
| `ops_engineer` | 运维工程师 | 负责处理工单、执行巡检、填写处理结果和查看相关设备资料 |
| `inspection_staff` | 巡检人员 | 负责执行巡检任务、填写检查项、上传巡检附件和发起异常转工单 |
| `inventory_manager` | 库存管理员 | 负责备件维护、备件出入库、库存流水和库存预警处理 |
| `supplier_manager` | 供应商管理员 | 负责供应商资料维护、查看供应商关联设备和服务记录 |
| `knowledge_manager` | 知识库管理员 | 负责知识库文章维护、发布和分类管理 |
| `ops_viewer` | 运维观察员 | 只读查看业务数据、报表和台账，不允许修改业务数据 |

## 五、数据权限建议

| 角色 | 数据范围建议 |
|---|---|
| 运维主管 | 可查看和管理当前组织及下级组织的全部 OPS 数据 |
| 运维工程师 | 可查看当前组织下设备、分派给自己的工单、参与处理的工单和相关巡检记录 |
| 巡检人员 | 可查看当前组织下分配给自己的巡检任务、巡检记录和由本人发起的异常工单 |
| 库存管理员 | 可查看当前组织下备件、库存流水、库存预警和供应商基础信息 |
| 供应商管理员 | 可查看和维护当前组织下供应商资料及关联信息 |
| 知识库管理员 | 可查看和维护当前组织下知识库文章 |
| 运维观察员 | 可只读查看当前组织及授权范围内的业务数据 |

数据权限建议优先使用业务表中的 `level_mark_id`、`level_mark_value` 配合框架组织架构能力实现。

## 六、实现要求

1. 前端菜单路由应根据页面权限动态展示。
2. 页面按钮应根据操作权限动态展示或禁用。
3. 表格操作列应按权限控制，例如没有 `ops:work-order:dispatch` 时不显示“分派”。
4. 后端接口必须校验操作权限，不允许只依赖前端隐藏按钮。
5. 批量操作、删除、审核、关闭、出入库等高风险操作必须做二次确认。
6. 权限标识应保持稳定，避免上线后频繁变更导致已有角色授权失效。
