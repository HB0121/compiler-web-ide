《智能系统开发》课程综合实验报告
实验名称： 基于大语言模型的智能校园帮办系统（Campus-Helper）设计与实现
姓名： 黄彬
院系： 计算机系

一、 实验目的
掌握前沿 AI 技术的工程化落地： 突破传统表单交互的限制，利用本地大语言模型（LLM）实现自然语言的意图识别与结构化数据抽取。

掌握企业级全栈开发架构： 熟练运用 Vue 3 与 Spring Boot 3 构建前后端分离架构，掌握跨域处理、无状态鉴权及统一路由拦截。

深入理解事务控制与数据一致性： 在涉及虚拟钱包余额流转、信用分更新等核心业务中，利用 Spring 声明式事务保证多表操作的强一致性。

提升复杂工程问题的排错能力： 掌握通过后端控制台日志定位异常（如 JSON 反序列化异常、文件上传超限等）并给出有效解决方案的能力。

二、 实验环境与技术栈
前端工程： Vue 3 (Composition API) + Vite + Vant UI + Axios + Vue Router

后端工程： Spring Boot 3 + MyBatis-Plus + Spring AI (Ollama)

数据库与中间件： MySQL 8.0

核心工具： 本地 Ollama 模型引擎、JWT (JSON Web Token) 鉴权库

三、 系统核心架构与原理
本系统采用标准的微服务雏形架构，分为四大核心模块：

安全与鉴权中心： 放弃传统的 Session，采用基于 JWT 的无状态认证体系。前端通过 Vue Router 的 beforeEach 实现路由守卫，后端通过配置 WebMvcConfigurer 和自定义 JwtInterceptor 实现“安检门”，拦截非法请求。

AI 智能语义引擎： 用户输入口语化需求（如“去2栋拿个快递，赏15元”），后端通过 Spring AI 框架跨进程调用本地大模型，将非结构化文本解析为包含时间、地点、动作、金额和标签的 DTO 对象。

交易与状态机控制： 任务状态在“待接单”、“进行中”、“已完成”间流转。资金（balance）的冻结、扣款以及信誉分（credit_score）的结算，全部封装在 @Transactional 事务中。

多媒体静态资源服务： 后端配置资源映射（ResourceHandler），将物理硬盘上的 /uploads/ 目录暴露为可通过 HTTP 直接访问的图片服务器。

四、 实验步骤与核心实现细节
1. JWT 鉴权防线的搭建
首先在后端编写了 JWT 工具类用于生成和解析 Token，并在拦截器中提取请求头中的 Authorization 字段。若无合法门票，直接返回 401。前端则在 Axios 的请求拦截器中统一注入 Token，实现了无感知的鉴权交互。

2. 提示词工程 (Prompt Engineering) 与 AI 接入
在开发 TaskAiService 时，遇到了大模型自作主张输出嵌套 JSON 对象，导致后端 Jackson 抛出 MismatchedInputException 异常的问题。

解决思路： 未修改 Java 实体类迁就 AI，而是通过优化 System Prompt（系统提示词），增加强制约束：“核心警告：所有字段的值必须是基本的字符串或数字，绝对不允许输出嵌套的 JSON 对象...”，并给出了 Few-Shot（少样本）示例。最终成功将不可控的大模型输出规范化。

3. 基于事务的资金流转闭环
在 TaskService 中，设计了发单扣款与结算打款的核心逻辑。

发单扣款： 在执行 taskMapper.insert() 前，先校验发布者余额 balance.compareTo(reward) < 0，若余额不足则抛出运行时异常，利用 @Transactional 阻断发单。

结算打款： 封装了 completeTaskWithReview 方法，将“任务状态更新为已完成”、“写入评价记录表”、“增加接单人钱包余额”、“动态计算并更新接单人信用分”四个操作强绑定在同一事务中，实现了安全的分布式交易雏形。

4. 文件上传与静态资源管理
在实现任务附图功能时，遇到了 ERR_CONNECTION_RESET 的网络异常。

排错与实现： 经查阅日志定位为 Spring Boot 默认单文件 1MB 大小限制所致。在配置文件中将 spring.servlet.multipart.max-file-size 提升至 10MB。随后通过重写 WebConfig 的 addResourceHandlers 方法，成功将本地保存的图片流转化为可通过 URL 访问的网络资源，并存入数据库的 image_url 字段。

五、 实验结果与测试
意图解析测试： 针对口语化的长难句输入，系统能稳定、极速地提取出“时间、地点（自动合并起点与终点）、动作、赏金”并渲染在前端表单中，无 JSON 解析崩溃现象。

交易一致性测试： 当模拟发单人余额不足或恶意篡改前端请求时，后端风控精准拦截并抛出提示。任务完成后，数据库中发单人的扣款与接单人的进账数据完美守恒，信用分正常浮动。

系统整体表现： 前后端联调顺畅，V1.0 (MVP版本) 核心功能达到 Code Freeze（代码冻结）标准，具备了真实商业化部署的初步可行性。

六、 实验总结与心得
通过本次《智能系统开发》项目实战，我完成了从传统 CRUD（增删改查）思维向**“AI Agent + 全栈工程”**思维的跨越。
在面对大模型返回脏数据导致后端崩溃、文件上传导致连接重置等真实开发问题时，我学会了首选查看控制台报错日志（Stack Trace），并利用“提示词工程”这种低代码成本的手段解决复杂的业务场景问题。
此外，对 @Transactional 事务的运用让我深刻体会到企业级应用中“数据一致性”和“防超支拦截”的底线思维。虽然后续仍有“信用分低于60分限制发单”的风控模块有待完善，但当前系统的核心骨架已足够健壮，极大提升了我的工程架构视野与全栈落地能力。
