### 1. 需求分析与核心业务流

- **传统痛点**：校园互助信息（二手、跑腿）散落在各个微信群，信息格式不统一，匹配效率极低。
    
- **AI 赋能解决方案**：用户只需进行“一句话发布”（如：“明天中午求个同学去南区快递点帮拿个大件，打赏5块钱”）。
    
- **核心功能闭环**：
    
    1. **发布**：大模型对自然语言进行意图识别和实体抽取（NER），自动结构化为：`{时间: 明天中午, 地点: 南区快递点, 事件: 拿大件, 报酬: 5元, 状态: 待接单}`。
        
    2. **流转**：大厅展示结构化订单，支持条件筛选。
        
    3. **接单与状态机**：接单 -> 执行中 -> 确认送达 -> 互评。
        

### 2. 系统建模（报告的得分大头）

在这个题材下，你可以画出非常漂亮且逻辑严密的图表：

- **实体关系图 (ER 模型)**：
    
    - **核心实体**：用户 (User)、任务订单 (Task)、评价 (Review)。
        
    - **亮点设计**：在“任务订单”实体中，除了常规的字段，可以设计一个 `parsed_json` 字段，专门用来存储 AI 提取出的结构化数据，展现对 AI 结果的落库能力。
        
- **数据流图 (DFD)**：
    
    - **顶层图**：用户 <-> 帮办平台。
        
    - **0层/1层图**：清晰描绘出一条特殊的数据流：`非结构化需求描述 -> [AI 意图解析模块] -> 结构化任务数据 -> [任务分发模块]`。
        
- **UML 建模**：
    
    - **状态图 (State Diagram)**：这个系统最适合画状态图。描绘一个任务从 `待接单(Pending)` -> `进行中(In Progress)` -> `已完成(Completed)` 或是 `已取消(Cancelled)` 的完整生命周期。
        
    - **时序图 (Sequence Diagram)**：画一个前端 Vue 3 发起请求，后端 Spring Boot 接收后调用本地大模型（如 Ollama）进行文本解析，最后入库返回前端的交互时序。
        

### 3. 拟定的技术栈

- **前端**：Vue 3 + Vite搭建响应式界面。
    
- **后端**：Java (Spring Boot + MyBatis) 提供稳定的业务逻辑和接口。
    
- **AI 模块**：在后端接入本地部署的大模型（如基于 Ollama 运行的模型）或外部 API，利用 Prompt Engineering（提示词工程）让模型稳定输出 JSON 格式的解析结果。
