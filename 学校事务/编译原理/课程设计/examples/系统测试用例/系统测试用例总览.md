## 07 LLVM IR

目录：`07_LLVM_IR生成`

| 文件 | 类型 | 覆盖点 | 预期 |
| --- | --- | --- | --- |
| `llvm_branch_call.c` | 正常用例 | 函数调用、分支、局部变量、LLVM 验证 | IR 包含 `define i32 @main`、`alloca i32`、`br i1`、`ret i32`，LLVM Verify 显示 `Internal verifier: PASS` |
| `llvm_modulo_loop.c` | 正常用例 | 循环、取模、条件跳转 | IR 包含 `srem i32`、`br i1` |

4.2 验证重点：

- `LLVM IR` 输出为可导出的 `.ll` 风格文本，导出时同时生成 `llvm_ir.txt` 和 `llvm_ir.ll`。
- `LLVM Verify` 先执行内部静态验证：检查 `main` 定义、跳转目标 label、基本块终结符和 `ret`。
- 如果本机安装了 LLVM 工具链，可继续使用外部命令验证：

```powershell
llvm-as outputs/llvm_ir.ll -o outputs/llvm_ir.bc
lli outputs/llvm_ir.ll
clang -c outputs/llvm_ir.ll -o outputs/llvm_ir.obj
```

其中 `clang -c` 只验证 IR 能否被 LLVM 前端编译成目标文件，不进行链接；如果没有安装 Visual Studio/MSVC 运行库，优先使用这一条命令做外部合法性验证。

完整链接和运行验证需要在 `x64 Native Tools Command Prompt for VS` 中执行，确保 `cl`、`link`、`clang` 均可被找到：

```cmd
where cl
where link
where clang
clang outputs\llvm_ir.ll -o outputs\llvm_ir.exe
outputs\llvm_ir.exe
```

若仅出现 `overriding the module target triple` warning 而没有 error，且生成的 `outputs\llvm_ir.exe` 能运行，说明 LLVM IR 已通过外部编译、链接和运行验证。运行输出应与 GUI 中 `Interpreter` 的 `builtin write(...)` 或 `return_value` 对照一致。

## 08 CFG 与 DAG 优化

目录：`08_CFG与DAG优化`

| 文件 | 类型 | 覆盖点 | 预期 |
| --- | --- | --- | --- |
| `cfg_if_else.c` | 正常用例 | Leaders、基本块划分、if/else CFG | Basic Blocks 中有 Leaders 表，CFG 有前驱/后继 |
| `dag_common_subexpr.c` | 正常用例 | 基本块内公共子表达式 | DAG 中出现 `common:`，优化后减少重复 `a + b` |
| `cfg_dag_complex.c` | 综合用例 | 多基本块 CFG、多块 DAG、公共子表达式、DAG 优化目标代码 | Basic Blocks、CFG、DAG、DAG Optimized Quads 全部有输出，Optimized Target Code 行数少于 Target Code |

4.4 输出重点：

- `Basic Blocks` 包含 Leaders 表：

```text
Index | Block | Reason
--- | --- | ---
0 | B0 | entry; function entry main
```

- `CFG` 包含前驱和后继：

```text
Block | Successors | Predecessors
--- | --- | ---
B0 | B2, B1 | -
```

- `DAG Optimized Quads` 包含优化后指令数：

```text
DAG optimized quadruples
Optimized instruction count: 19
```

- `Optimized Target Code` 必须基于 DAG 优化后的四元式生成，不能只使用普通四元式优化结果。`cfg_dag_complex.c` 的目标代码行数对比应能体现优化效果：

```text
Target Code: 40 行左右
Optimized Target Code: 31 行左右
```

- 对 `cfg_dag_complex.c`，优化后目标代码中应能看到公共子表达式和常量传播/折叠效果，例如：

```text
MOV c, 15
MOV d, 15
MOV x, 225
```
