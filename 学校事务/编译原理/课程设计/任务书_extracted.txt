《编译原理课程设计》任务书
2023级
使用说明：
（1）本任务书用于指导教师进行《编译原理课程设计》的教学，也用于指导学生开展本课程的准备和学习。
（2）如课程分为多个班行课，原则上各班行课应与本任务书一致。
（3）对课程具体的教学方法，教师可依据课程目标进行灵活设计和实施。
（4）任课教师如需进行评分标准等重要调整，请提请课程组研讨，共同确定。
一、课程设计目的
本课程设计的目的是通过设计和实现一个小型编译器，加深对编译原理课程中学习的相关原理、技术和方法的理解和应用，提高算法分析、设计、实现与验证的能力，从而提升学生分析和解决复杂问题的能力。
学生在本课程中通过广泛搜集、阅读及整理资料，进行独立分析，形成设计方案，利用熟悉的开发工具，实现编译器的基本功能，完成课程设计报告。
学习本课程之后，学生应该掌握设计和实现编译器的一般性思路，掌握设计高级语言的语法和语义对应的上下文文法、属性文法和翻译方法，理解编译器各个构成部分涉及到的主要算法，能够搭建合适的开发环境，在每个阶段选择合适的算法，对实验的结果进行分析，能有效表达开发工具和实现的编译器的局限性，能够将设计结果用图表、设计报告、软件的方式有效地呈现。
本课程的具体目标有4个：
目标1：能够利用离散数学和形式语言的基本知识，对给定的简单语言设计其上下文无关文法和属性文法，对该语言的编译器进行分析，确定所设计的编译器的功能和应用环境，设计可行的设计方案。
目标2：能够选择合适的开发工具实现编译器的功能，并进行验证。
目标3：能够选择合适的测试工具，设计多组测试数据测试所实现编译器的功能，并能正确评价所选工具和所实现的编译器的局限性，最后完成课程设计报告。
目标4：了解新型编译技术和国产编译器，树立科技强国的远大理想和家国情怀。
二、课程设计要求
从课程设计的目的出发，通过课程设计工作的各个环节，达到以下教学要求：
（1）每个学生独立完成所选任务，并能以适当的方式展现所完成的成果。
（2）所写代码必须符合代码规范，如使用的类名、对象名、变量名、方法名等必须有明确的规范，在代码的适当位置有合适的注释，能够反映自己的学号姓名、代码的创建时间、功能等。
（3）设计完成后，每个学生均需参加答辩，系统实现及成果演示至少交由指导教师或助教检查1次。
（4）最后要求写一份详细的课程设计报告，要求结构清晰，文字通顺，能反映所完成工作的难度和工作量。

4.2 四元式到LLVM IR的简化转换器
目标：理解教材中的四元式与工业编译器（如毕昇编译器）LLVM IR的关系
要求：
读取四元式文件，将其转换为LLVM IR风格的中间代码并输出，支持赋值、加、减、乘、除、return语句、布尔表达式、if语句，其他语句选做；
能够识别普通变量、常量和临时变量，为普通变量生成alloca指令，中间变量不生成；
能够将算术四元式转换为 add/sub/mul/sdiv 指令，将赋值四元式转换为store指令，将返回四元式转换为ret指令及其他比较cmp和跳转br指令。
示例1：
输入：
0: (=, 10, _, a)
1: (=, 20, _, b)
2: (+, a, b, t1)
3: (=, t1, _, c)
4: (return, c, _, _)
输出（LLVM IR）：
define i32 @main() {  //定义函数，函数返回值类型是 32 位整数
entry:   //基本块标签
%a = alloca i32
%b = alloca i32
%c = alloca i32
store i32 10, ptr %a   //把整数10存入变量a的地址中
store i32 20, ptr %b
%v1 = load i32, ptr %a  //从变量a的地址中取出值，放入临时结果%v1
%v2 = load i32, ptr %b
%t1 = add i32 %v1, %v2
store i32 %t1, ptr %c
%v3 = load i32, ptr %c
ret i32 %v3
}
示例2：
输入：
0: (=, 10, _, a)1: (=, 20, _, b)2: (J>, a, b, 4)3: (J, _, _, 6)4: (=, a, _, max)5: (J, _, _, 7)6: (=, b, _, max)7: (return, max, _, _)
输出（LLVM IR）：
define i32 @main() {entry:%a = alloca i32%b = alloca i32%max = alloca i32store i32 10, ptr %astore i32 20, ptr %b%v1 = load i32, ptr %a%v2 = load i32, ptr %b
//icmp(integer compare)整数比较
//sgt(signed greater than)有符号大于%cmp1 = icmp sgt i32 %v1, %v2
//br(branch)分支跳转br i1 %cmp1, label %L4, label %L6L4:%v3 = load i32, ptr %astore i32 %v3, ptr %maxbr label %L7L6:%v4 = load i32, ptr %bstore i32 %v4, ptr %maxbr label %L7L7:%v5 = load i32, ptr %maxret i32 %v5}
注意：
alloca：给变量分配空间
store：把值写进变量空间
load：从变量空间取出值
在规范LLVM IR中，局部变量通常先是内存地址，参与运算前必须通过 load 取值，赋值时通过store写回。

4.4 编译前端局部优化与流图分析系统
目标：实现一个针对中间代码（四元式）的分析与优化系统。系统需能够将输入的线性中间代码序列自动划分为基本块，并在此基础上构建控制流图（CFG）。同时，系统需利用无环有向图（DAG）技术对基本块内部进行局部优化，识别并消除公共子表达式，最终实现优化前后代码的对比与可视化展示。
要求：
控制流分析 (Control Flow Analysis)
基本块划分：自动识别首语句（Leaders），根据划分规则将中间代码序列切分为独立的基本块。
CFG构建：分析基本块间的跳转关系，自动建立前驱和后继的控制流边。
可视化显示：以图形化界面展示控制流图。每个节点代表一个基本块，边代表控制流向。
基于DAG的局部优化 (Local Optimization)
DAG构建：为每个基本块构建对应的 DAG 结构。
公共子表达式识别：在构建 DAG 过程中，通过节点合并逻辑自动识别公共子表达式。
DAG合并与转换：支持将多个操作合并到同一 DAG 节点，并根据 DAG 重新生成优化后的代码。
可视化显示：以图形化界面展示基本块的DAG。
挑战加分项（选做）
全局数据流分析：在 CFG 基础上实现活跃变量分析。
死代码消除：在 DAG 重构代码阶段，自动剔除未被后续引用的计算节点。
循环识别：在流图中自动标注出自然循环（Natural Loops）。
示例输入：
// 测试程序：仅支持顺序、选择、循环和函数调用,不包含数组和指针
int calculate_power(int base, int exp) {
int res;
int i;
res = 1;
i = 0;
// 循环结构测试：基本块划分与回边识别
while (i < exp) {
res = res * base;
i = i + 1;
}
return res;
}
void main() {
int a,b,c,x,y,z,result;
a = 10;
b = 5;
c = 2;
// 1. 顺序结构与大量公共子表达式测试 (用于检测 DAG 合并)
x = a + b;           // 表达式 1
y = b * c;           // 表达式 2
z = a + b;           // 公共子表达式 (应与 x 合并)
result = x * (a + b); // 进一步冗余 (a+b 再次出现)
result = result + (b * c); // (b*c 再次出现)
// 2. 选择结构测试 (用于检测 CFG 边的自动建立)
if (result > 100) {
// 分支 A
x = y + z;
y = y + z;       // 局部公共子表达式
calculate_power(x, 2);
} else {
// 分支 B
x = a - b;
z = a - b;       // 局部公共子表达式
}
// 3. 复杂表达式与代数化简测试
a = a + 0;           // 代数化简：加0
b = b * 1;           // 代数化简：乘1
c = c * 0;           // 代数化简：乘0
// 4. 函数调用

}
