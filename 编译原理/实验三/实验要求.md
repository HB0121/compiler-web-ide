【问题描述】

请根据给定的AST文件设计并实现语义分析程序，能诊察出常见的语义错误，输出错误信息，输出符号表，符号表可以分为常量表、变量表和函数表。为了方便自动评测，输入输出及处理要求如下：  

（1）输入的被编译源文件统一命名为 input.txt ；错误信息输出到命名为 output.txt 的结果文件中，常量表输出到命名为 const.txt 的结果文件中、变量表输出到命名为var.txt 的结果文件中，函数表输出到命名为 function.txt 的结果文件中；

（2）结果文件中包含两种信息：错误所在的行号 错误类型编码 （行号与类型编码之间只有一个空格），其中，错误类型编码严格按照表格中的编号输出，行号从1开始计数： 

|   |   |   |
|---|---|---|
|错误类型|错误类型编码|说明|
|名字重复声明|301|常量名或者变量名在当前作用域下重复定义。注意，变量是同一级作用域下才会判定出错，不同级作用域下，内层会覆盖外层定义。报错行号为重复定义语句所在行数。|
|名字未声明使用|302|常量名或者变量名在使用之前未定义，报错行号是变量/常量使用所在行。|
|函数重复声明|303|报错行号为重复定义函数语句所在行数。|
|函数未声明调用|304|函数在调用之前未定义，报错行号是函数调用所在行。|
|函数参数个数不匹配|305|函数调用语句中，参数个数与函数定义中的参数个数不匹配。报错行号为函数调用语句的函数名所在行数。|
|函数参数类型不匹配|306|函数调用语句中，参数类型与函数定义中对应位置的参数类型不匹配。报错行号为函数调用语句的函数名所在行数。|
|有/无返回值的函数与return语句不匹配|307|包括无返回值的函数包含了return或有返回值的函数缺少return或存在不匹配的return语句。报错行号为函数结尾的’}’所在行号。|
|break语句使用有误|308|break语句不在循环/switch中或缺少break语句，若循环缺少break语句则报错在循环结尾的’}’所在行号，若switch缺少break语句则报错在当前case语句的结束行。|
|改变了常量的值|309|报错行号是给常量赋值所在的行数。|
|运算对象类型不匹配|310|四则运算的运算对象类型不匹配，如int和double进行加法运算。报错行号是表达式所在的行数。|

  

（3）所有错误都不会出现恶意换行的情况，包括字符、字符串中的换行符、函数调用等等。 

（4）检查类型是否匹配时，不考虑隐式转换，只要类型不一致就报错。

（5）其他类型的错误，错误的行号以能够断定发现出错的第一个符号的行号为准。例如有返回值的函数缺少返回语句的错误，只有当识别到函数末尾的}时仍未出现返回语句，才可以断定出错，报错行号即为}的行号。

【输入形式】input.txt 中的是存在语义错误的AST。  

【输出形式】按如上要求将错误处理结果输出至 output.txt 中。

【样例输入】

Program  
  FunctionDecl(int main)[3]  
    Compound  
      VarDecl(int a)[4]  
        10[4]  
      VarDecl(float c)[5]  
        3.14[5]  
      VarDecl(char d)[6]  
        A[6]  
      VarDecl(int a)[7]  
        20[7]  
      VarDecl(int sum)[8]  
        +[8]  
          a[8]  
          b[8]  
      VarDecl(float product)[9]  
        *[9]  
          d[9]  
          c[9]  
      ReturnStmt[10]  
        0[10]

7 301  
8 302  
9 310

（1）上表中只列举了部分错误类型和报告该错误类型的情况，未包含的错误类型或错误情况，需要自行设计，本次作业考核不涉及；

（2）完成本次作业时，请勿输出词法分析和语法分析作业要求输出的内容；

（3）在本次考核之外，发现错误时最好直接输出描述信息，而不是仅给出错误类别码，有助于完善编译器的设计、开发与调试。

（4）每一行中最多只有一个错误。

（5）本次作业需要建立符号表。
